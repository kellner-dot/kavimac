# KaviGuard v1.1.0 "Server Guard" — Design Document

**Date:** 2026-10-01 · **For:** Seth · **Machine:** Seths-MacBook-Air
**Status:** Design approved for build — not yet implemented

## 1. Machine profile (what we're designing for)

- MacBook Air (Late 2020), Apple M1, **8 GB unified RAM**, macOS 27.0
- Current state: ~76% RAM used, ~58% disk used
- **Role: always-on server first** — BlueBubbles iMessage bridge (port 1234),
  Mac RVD agent (port 8899), Tailscale tunnel. Music + streaming second. Gaming: never.
- Owner constraints: **free only**, no scareware, no surprise reboots, no auto-updates,
  nothing deleted without a restore path (Seth's standing rule).

## 2. Goals / non-goals

**Goals:** keep the server alive and healthy with minimal footprint; reclaim disk
safely; give Seth visibility (not anxiety) into RAM/disk/services; everything
undoable and plain-English.

**Non-goals:** no malware engine (XProtect + Gatekeeper already cover it), no fan
control (the Air is fanless), no SSD TRIM toggles (macOS handles Apple SSDs natively),
no "RAM boost" button (snake oil — causes swap storms), no subscription/trial upsells,
no disabling SIP, no touching `/System`.

## 3. What v1.0.0 already does (kept as-is)

- `cleanup.sh`: user caches (Safari/Finder excluded), system caches (sudo subset),
  Trash, logs older than 7 days, DNS flush, Xcode DerivedData — reports bytes freed
- `optimize.sh`: login items report, Spotlight/FileVault/update/memory-pressure reports,
  server tweaks check (AC sleep 0, womp, reduce transparency)
- `health.sh`: CPU, memory, disk, battery (cycles + health %), network + Tailscale, power
- `services.sh`: BlueBubbles :1234, RVG :8899, Tailscale status
- `vpn.sh`: KaviVPN WireGuard status/auto-reconnect
- `kavimac-monitor.sh`: LaunchAgent loop — service checks, 90% disk warning,
  heavy-swap warning, macOS notifications

## 4. v1.1.0 features (ranked by value for this machine)

### 4.1 Protected-services guardrail (core of the release)
Every KaviGuard action — cleanup, optimize, uninstall, maintenance — runs through a
**hard whitelist**: BlueBubbles server, `rvd-mac` agent, Tailscale, KaviGuard itself.
Rules:
- No "kill background processes", no memory purges, no LaunchAgent/Daemon unloading
  unless Seth confirms each item by name.
- New `--services` output becomes a live dashboard: each service alive + port-responding,
  uptime, restart count since last boot.
- The background monitor keeps its current checks and gains: **auto-restart attempt**
  for BlueBubbles if port 1234 stops responding (2 tries, then notify — never an
  infinite restart loop).

### 4.2 Never-sleep / power-assertion verifier
The machine's entire job is staying awake. On every run, KaviGuard verifies and
reports drift from the known-good baseline, with one-command re-apply:
- `pmset`: AC sleep `0`, `autorestart 1`, `womp 1`; display may sleep (fine).
- **Lid-close guard** (the #1 silent server killer on a MacBook): check that a
  lid-close mitigation is alive — `caffeinate` assertion held by a LaunchDaemon
  (preferred, zero new deps) or Amphetamine (free). If the guard is dead, notify
  loudly: "the server is a sleeping laptop right now."
- Re-apply is opt-in via `--fix-power`, never automatic.

### 4.3 Safe junk sweep (bounded, preview-first)
Extends today's cleanup with strict boundaries:
- Allowed: `~/Library/Caches`, `/Library/Caches`, browser caches, rotated logs,
  `/private/tmp`, `/var/folders` scratch, user Trash.
- **Preview mode by default**: list what will be removed + sizes, delete on confirm.
  `--yes` for trusted reruns.
- Everything goes to Trash first (recoverable), never `rm` straight to oblivion.
- Expensive rebuilds (Spotlight reindex, font caches) are **opt-in only** — they peg
  an 8 GB machine and must never run silently.

### 4.4 Complete uninstaller with orphan scan
Pearcleaner-pattern, CLI-first:
- `kavimac.sh --uninstall <App>`: removes app + associated caches, preferences,
  logs, Application Support, LaunchAgents, login items.
- `--find-orphans`: scans for leftovers from long-removed apps (the "why is my disk
  full" creep on a small Air SSD). Preview + confirm, trash-first.
- Never touches anything on the protected-services whitelist.

### 4.5 Disk space visualizer
- Built-in: size-sorted directory browser (`--disk`) for `/`, `~`, and the music/
  streaming library folders — "you can't clean what you can't see."
- Recommends (not bundles) the free visual tools: Radix (modern sunburst, OSS) or
  GrandPerspective. No paid DaisyDisk needed.

### 4.6 Startup & launchd manager
- One view of **all** login items + LaunchAgents/Daemons (user and system):
  `kavimac.sh --startup`.
- Enable/disable with guardrails: whitelisted services can't be disabled; everything
  else shows what it is in plain English before Seth decides.
- This is the most underserved pain point in the market — and the main defense
  against silent RAM creep on 8 GB.

### 4.7 Memory-pressure monitor (menu bar)
- Lightweight menu-bar readout: memory pressure + top 5 hogs. **No "boost" button.**
- Implementation: recommend free OSS **Stats** (~1% CPU) or a tiny SwiftBar plugin
  reading `memory_pressure`/`vm_stat`. Visibility, not snake oil.

### 4.8 Conservative language-file pruner (opt-in)
- Monolingual-pattern, `kavimac.sh --prune-languages`: keep English (+ any language
  Seth names), strip the rest. Typical reclaim: 1–4 GB.
- **Architecture stripping OFF by default** (this is the tab that has broken apps,
  Adobe famously). Report-only first run.

### 4.9 On-demand maintenance runner
- `kavimac.sh --maintenance`: run macOS periodic scripts (daily/weekly/monthly),
  verify startup-disk structure, rebuild Spotlight/LaunchServices/Mail databases
  **only when symptomatic** (OnyX-proven value, but never a scheduled surprise on
  a server).

### 4.10 APFS snapshot + purgeable-space manager
- `kavimac.sh --snapshots`: list Time Machine local snapshots + purgeable space,
  thin them with `tmutil thinlocalsnapshots` on confirm. The invisible space eater
  no paid suite surfaces well — honest free-space accounting in `--health` too.

### 4.11 Update checker (report-only)
- Flags macOS + App Store + Homebrew updates. **Never auto-installs, never reboots.**
  A server must not self-reboot.

### 4.12 Undoable-by-default + plain-English action log
- Every destructive action: to Trash or logged with a restore path.
- `~/Library/Logs/kavimac.log`: each run appends what was checked, what was
  removed, what was skipped and why — one sentence per action, no jargon.
- This is the trust differentiator vs CleanMyMac/MacBooster scareware — and it
  matches Seth's verify-before-delete rule.

## 5. Safety rules (apply to every version)

1. SIP stays enabled. `/System` is never touched.
2. Whitelisted services are never killed, purged, or unloaded.
3. No auto-reboots, no auto-updates, no scheduled surprise maintenance.
4. Cache clears that trigger expensive rebuilds are opt-in.
5. Free-RAM "boosters" are banned from the codebase by design.
6. Network config (Tailscale bridge) and power baseline are verified, changed only
   with `--fix-*` and Seth's say-so.
7. Every destructive action is trash-first or logged-with-restore.

## 6. CLI surface (v1.1.0)

```
kavimac.sh                  full run: guardrail check + cleanup(preview)
                            + optimize + health + services
kavimac.sh --cleanup        safe junk sweep (preview by default, --yes to apply)
kavimac.sh --uninstall <App>  complete uninstall + leftovers
kavimac.sh --find-orphans   leftover scan for long-removed apps
kavimac.sh --disk [path]    size-sorted disk browser
kavimac.sh --startup        login items + launchd manager
kavimac.sh --snapshots      APFS local snapshots + purgeable space
kavimac.sh --prune-languages  conservative language prune (opt-in)
kavimac.sh --maintenance    on-demand periodic scripts + DB rebuilds
kavimac.sh --fix-power      re-apply known-good power baseline
kavimac.sh --health / --services / --optimize   (unchanged from v1.0.0)
```

Background monitor gains: BlueBubbles auto-restart attempt, lid-close guard check,
snapshot/purgeable-space in the disk warning.

## 7. Implementation notes

- Stay **bash-native, Apple Silicon, zero new dependencies** — same philosophy as v1.0.0.
- Menu bar: don't build one; recommend Stats (free, OSS). If Seth wants it in-house
  later, a SwiftBar plugin is the lightest path.
- Lid-close guard: `caffeinate -i` assertion held by a LaunchDaemon is the
  dependency-free option; Amphetamine is the free GUI fallback.
- All new destructive paths funnel through one `trash_first()` helper so the
  undoable rule can't be accidentally bypassed.
- Test on the Air via the rvd-mac agent before calling it done; bump VERSION to 1.1.0.
